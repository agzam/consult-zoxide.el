#+TITLE: consult-zoxide changelog

* 0.1.0

Initial release.

- ~consult-zoxide~ jumps to a directory from the zoxide database, keeping zoxide's frecency order.
- ~consult-zoxide-read~ prompts and returns a path, honouring the shell ~z~ contract of skipping the prompt when a query singles out one directory.
- Annotations: frecency score on every row, plus the branch for git checkout roots, read straight out of ~HEAD~ and only for rows on screen. The branch is suppressed where it merely repeats the directory name.
- Narrowing on ~g~ git checkout roots, ~w~ worktrees, ~d~ entries whose directory is gone. Worktrees and submodules are told apart by reading the gitdir their ~.git~ file names, resolved against the directory to cope with the relative form submodules use.
- Dead entries are excluded by default and included under a prefix argument, so they can be narrowed to and pruned.
- ~consult-zoxide-remove~ drops entries in one batched call, and asks first when a bulk removal includes a directory which still exists. The question names the batch size and the live count, a mis-narrowed ~embark-act-all~ being the case worth catching; a deliberate selection goes through on one keypress.
- ~consult-zoxide-directories~ returns the bare path list, for feeding another completion source.
- A ~consult-dir~ source, appended to ~consult-dir-sources~ under the ~z~ narrowing key by ~consult-zoxide-consult-dir-register~, with no hard dependency on ~consult-dir~. Its rows carry the Embark actions below, removal key included: they tag themselves ~consult-zoxide-dir~ for Embark while the source still declares the ~file~ category ~consult-dir--pick~ needs.
- ~consult-zoxide-track-mode~ teaches zoxide about directories visited in Dired, and stays out of Dired's way where zoxide is not installed.
- Optional Embark integration in ~consult-zoxide-embark~, switched on by ~consult-zoxide-embark-register~: the ~consult-zoxide-dir~ category inherits ~embark-file-map~, removal is a multi-target action on ~\~, and ~d~ joins ~D~ at ~delete-directory~ behind Embark's own confirmation. ~embark-quit-after-action~ stays the user's to set; the prompt that survives a removal comes back without the removed rows, which takes working around ~embark--restart~ seeing no minibuffer when a multi-target action's post hooks run.
- Removing one entry names its full path; the count wording is reserved for a batch.
- Neither integration registers itself. Installing the package leaves Embark and ~consult-dir~ untouched until the config calls a register function.
